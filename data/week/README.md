# One-week dataset (synthetic) - 5 to 11 October 2026

Generated by `sim/generate_week.py` (fixed random seed, reproducible). It stands in for one week of
captured wearable data until the hardware has been worn in the field. Replace it with real logs later;
`sim/analyse_week.py` works on either.

**Everything here is synthetic.** The farm is invented (Vellore district, Tamil Nadu, origin 12.9200 N,
79.1300 E). Pesticide parameters are illustrative placeholders, not label or regulatory values.

## Scenario
- 6 plots (P1 paddy, P2 tomato, P3 groundnut, P4 brinjal, P5 banana, P6 chilli), a shed and a diesel pump.
- 7 spray events (S1-S7) during the week, including two tank mixes; REIs of 12, 24 and 48 h.
- 5 workers (W01-W05), Monday to Saturday, 07:00-16:00 (Saturday to 12:00); Sunday off.
  W05 is flagged vulnerable (alert thresholds halved).
- Planned events: W03 enters P2 during its REI on Monday and ignores the alarms (supervisor arrives after
  escalation); W02 (Tue), W05 (Tue), W04 (Thu) and W03 (Sat) step into active plots and leave when warned;
  W04 has a supervisor-authorised early entry into P6 on Friday; W01 harvests in plots whose REI has
  expired (dose accumulates without any REI violation); GPS is poor under the banana canopy and near the
  shed roof; rain on Thursday afternoon (humidity 95%); W02 does not wear the device on Thursday afternoon.
- Workers react to the device (they leave when warned, press ACK), so the data is closed-loop.

## Files
| File | Content |
|---|---|
| `farm/plots.csv`, `farm/plots.geojson`, `farm/landmarks.csv` | plot polygons (lat/lon), shed, pump |
| `pesticides.csv` | product id, REI h, AOEL mg/kg/day, dermal absorption, DT50 days, DFR0 (illustrative) |
| `spray_records.csv` | spray id, plot, products, application end time, rate, applicator, zone REI, REI end |
| `workers.csv` | worker id, role, body weight, PPE penetration factor, vulnerable flag, device id |
| `early_entry_authorisations.csv` | supervisor authorisations (Friday, W04, P6) |
| `weather_hourly.csv` | temperature and humidity used by the generator |
| `sensor_windows_5s/Wxx.csv` | **main dataset**: one row per 5 s window per worker (177,120 rows) |
| `raw_1hz/Wxx_YYYY-MM-DD.csv.gz` | 1 Hz node log per worker-day (885,600 rows); replayed by gateway/pestguard_gateway.py --replay |
| `ground_truth/Wxx_YYYY-MM-DD.csv.gz` | true position, plot, activity, task, inside-active-spray flag (evaluation only) |
| `outputs/alerts.csv` | every alert level change (time, worker, from, to, HI, zone, REI minutes left) |
| `outputs/daily_dose.csv` | dose per product (mg/kg bw) and hazard index per worker per day |
| `outputs/week_results.json` | all numbers reported in IDF-B Section 8 |
| `outputs/firmware_vs_python.json` | Wearable firmware logic (compiled for PC) versus Python model, per worker-day |
| `outputs/gateway_replay_test.json` | Monday replayed through the gateway: lines sent / logged, alerts matched |
| `figures/fig01..fig07.png` | black-and-white figures used in the documents |

### Columns of `sensor_windows_5s`
time (IST, end of window) · lat, lon (last fix) · hdop · sats · acc_x/y/z_mg (mean, milli-g) · acc_sd_mg
(mean 1 s standard deviation of acceleration magnitude) · temp_c · rh_pct · mq135_mean, mq135_max (ADC counts)
· vcc_mv · activity (rest / walk / hand, from the IMU rule) · alert_max (highest level in the window) ·
alert_last · hazard_index (today, dimensionless) · zone_code (zone index x 10 + 1 near / 2 inside, -1 none) ·
rei_min_left (-1 if no active REI) · authorised (1 during supervisor-authorised entry) · gnss_uncertain (HDOP > 5).

### Columns of `raw_1hz`
Same quantities at 1 s: time, lat, lon, hdop, sats, acc_x/y/z_mg, acc_sd_mg, temp_c, rh_pct, mq135_raw,
vcc_mv, activity, alert_level, hazard_index, zone_code, rei_min_left, authorised.
